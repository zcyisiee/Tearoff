# v5 产品决定与未完成项

状态：**部分实现**。“已定并实现”一节描述现状；其后两节是没做或没验证的，不能当作现有能力。

## 背景

4.x（Swift）的问题由用户在 2026-11-15 提出：主页卡片太多太杂；记东西要手打 Markdown 标记；卡片与展开后的编辑器风格割裂；文件夹卡片快速拖文件必白屏；只支持 macOS。

## 已定并实现

| 决定 | 理由 | 由谁定 |
|---|---|---|
| 统一技术栈 Tauri 2（Rust + Web），放弃双端各写一套 | 富文本编辑、样式一致、Windows 三件事在 Web 编辑器里是同一个组件；单人项目不维护两份编辑器 | 用户选定 |
| 主页“今天优先”：今天的纸常开可写 → 固定的卡片 → 其余笔记一行一条、点开才展开 | 回到“撕张纸就记”；历史靠列表和搜索找 | 用户选定 |
| 文件夹卡片保留在主页，与固定笔记混排 | 用户在日常使用 | 用户选定 |
| 底层仍是 `.md`；格式靠格式栏、选中浮条、`/` 菜单、快捷键 | 不再手打标记 | 用户要求 |
| 卡片就是编辑器；展开是同一元素的变形动画 | 从结构上消除割裂 | 用户要求 + 实现选择 |
| 独立 sidecar `v5.json`，旧 `meta.json` 只读 | 新旧版本可并存、可回退 | 实现选择 |
| 去掉标签、卡片颜色、文件夹页签、应用内回收站、大纲、多库切换、自动归档 | 与“简洁随手记”无关；删除改走系统废纸篓 | 实现选择，**待用户确认** |
| 默认库是新的 `~/Documents/Tearoff`，不自动指向旧库 | 在用户决定之前不碰真实笔记 | 实现选择 |

## 尚未实现

- 卡片拖拽排序（现在是“⋯”菜单里的上移/下移）。
- 文件夹卡片：原生文件图标、高度拖拽调整、框选、Quick Look、键盘导航、Option 拖拽为复制。
- 图片拖入编辑器（现在只支持粘贴）；表格的行列增删按钮（现在只能插入 3×3 后编辑内容）。
- 开机启动、自动更新、多语言（界面目前只有简体中文）。
- 设置里录制快捷键（现在是手填字符串）。
- Windows 安装包与 CI；应用签名。
- 旧版发布流水线的路径更新（见开发指南“交付”）。

## 尚未验证

- **Windows 全部**：代码按跨平台写，但从未在 Windows 上编译或运行。
- **边缘悬停唤出、离开自动收起、失焦收起、快捷键、托盘**：实现了，编译通过，没有实测（需要真人移动鼠标；自动化会抢用户的光标）。已实测的只有：启动、窗口定位到光标所在显示器、不抢焦点地显示、界面滑入。
- 面板能否盖在全屏应用上（设了 `FullScreenAuxiliary`，未试）。
- 系统级文件拖出到 Finder 以及拖回来的整条链路（文件移动本身有测试；拖拽手势没有实测）。
- 大库性能：`get_state` 每次全量扫描并读每个文件前 2.4KB，几千篇以上未测。
- 旧库 `~/Documents/EdgeMark` 的真实导入（只用构造的 `meta.json` 测过）。
