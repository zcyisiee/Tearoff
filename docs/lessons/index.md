# 经验

每条：结论 → 适用边界 → 依据。

1. **需要“结束事件”才能复位的状态，一定会有收不到结束事件的一天。** 能从当前事实算出来的（光标在哪、键是否按着、磁盘 mtime），就每次现算；必须记的状态，由拥有事件流的一方负责清理，并且兜底条件要覆盖所有类型。
   边界：纯 UI 动画的过渡态不在此列。依据：`docs/issues/finder-card-blank.md`；v5 的 `panel.rs` 用轮询而非 enter/leave。
2. **同一块屏幕区域不要让两个手势系统各自识别拖拽。** SwiftUI 手势能看到内嵌 AppKit 视图的事件；谁先到阈值与拖动速度有关，所以 bug 只在“快”的时候出现。依据：同上。
3. **修不好的 bug，先怀疑根因模型。** 四轮“恢复渲染”的补丁都无效，是因为状态本来就说“应当透明”。对比“出问题”和“正常”两次的同一份诊断输出（视图树 diff），比继续加补丁快。
4. **所见即所得编辑 Markdown，要用机制保证不损坏文件，而不是指望序列化器完美。** 三道闸：打开不写、往返无损才进富文本、冲突另存副本。依据：`src/editor/markdown.ts`、`NoteEditor.tsx`；实测 Tiptap 会转义公式、丢行内 HTML、仅仅打开就重排表格。
5. **macOS 多显示器下不要用 tao/Tauri 的“物理坐标”定位窗口。** 不同缩放的显示器共用一个逻辑点空间；用 CoreGraphics（光标、显示器边界，线程安全）和 NSScreen（可用区域，主线程）取逻辑坐标，再用 `LogicalPosition` 设置。依据：首次实现把窗口放到了错误位置和尺寸。
6. **文件监听返回规范化路径。** `/tmp/x` 的事件以 `/private/tmp/x` 到达；比较前两边都 canonicalize，回给界面时用界面认识的原路径。
7. **Tauri 的 `csp` 在开发模式也生效**，会拦掉 Vite 注入的内联脚本，表现为窗口空白且无任何报错输出。开发用 `devCsp` 放开。
8. **状态类名的选择器要比它覆盖的规则更具体。** `:root[data-side="left"] .panel.is-native` 压过了 `.panel.is-native.is-shown`，面板在左侧模式下永远停在屏幕外。
9. **在真实应用里跑的自检，比 mock 上的测试更早暴露跨边界问题。** 第 5–8 条全部是 `src/selftest.ts` 或原生窗口截图发现的，浏览器里的 mock 一条都看不出来。
10. **在别人的机器上装依赖前先看上级目录有没有工作区文件。** `~/pnpm-workspace.yaml` 会让 pnpm 把子目录项目装进 home 的锁文件。
